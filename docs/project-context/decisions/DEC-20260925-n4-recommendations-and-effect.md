# Рекомендации и прямой эффект на уровне N4

## Решение

- Основная единица работы ассистента — конкретная товарная позиция N4.
- Формируются два независимых списка до пяти N4: по истории клиента и по нише.
- Рекомендоваться могут только N4, отсутствующие в текущем заказе.
- Одинаковая N4 не дублируется между списками; приоритет имеет персональный список.
- Слабые позиции не добавляются только ради заполнения пяти строк.
- Строка заказа только с N3 поддерживается для совместимости, но блокирует
  рекомендации всех N4 этой N3, поскольку конкретный товар неизвестен.
- В прямой эффект входят только показанные рекомендации N4, которые затем добавлены
  и фактически отгружены.
- Учитываются два сценария: добавление в исходный заказ и добавление в первый
  подходящий новый заказ того же клиента в пределах двух рабочих дней.
- Два рабочих дня означают понедельник–пятницу без учёта официальных праздников.
- Повторные показы и конкурирующие рекомендации не должны задваивать эффект.

## Совместимость

Входные и выходные форматы интеграции 1С не меняются: необходимые `n3_id`, `n4_id`,
`client_id` и `order_id` уже присутствуют. Старая N3-витрина эффекта сохраняется;
точная N4-атрибуция предоставляется отдельно.

## Ограничения

- Для доказательной атрибуции `/api/analyze` должен вызываться с `order_id`.
- Денежный эффект требует внешней EBITDA на тонну N4 и пока не рассчитывается сервисом.
- Календарь государственных праздников не применяется.
