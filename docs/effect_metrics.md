# Метрики расчёта эффекта ИИ-ассистента (внутренний)

Внутренняя спецификация. Клиентские версии — `docs/Заказчик/`. Источник требований —
письмо С. В. Рудакова («А ГРУПП») от 15.08.2026 + уточнения механики.

Итог — дашборд с таблицей эффекта, удельной EBITDA и денежным эффектом.

> Принцип: ассистент **сам не добавляет** позиции. Эффект **вычисляем из данных**
> (состояния заказа + наш журнал рекомендаций), **без сопоставления заказ↔заказ** и
> **без новых полей от 1С**.

---

## 0. Механика 1С

- Заказ живёт ~2 дня, потом закрывается (правки — только пока открыт).
- Статуса «отгружен/не отгружен» на самом заказе в 1С нет — учитывать ли отгрузку,
  уточняется с заказчиком.
- Историю заказов 1С шлёт дельтой (при изменении — заказ целиком) — это уже даёт
  все состояния заказов.

---

## 1. Модель: три состояния заказа

- **O** — оригинальный состав (на момент рекомендации);
- **R** — что порекомендовала система;
- **F** — финальный состав заказа.

Добавленное = **F − O**.

**Откуда:**
- **O и R** — из **журнала рекомендаций**. Ключевой факт: `POST /api/analyze`
  (`app/api/analysis.py`) инициирует 1С в момент разбора заявки, и его тело несёт
  **черновик заказа (O)** + возвращает **рекомендации (R)**. Сейчас эндпоинт
  stateless — нужно **начать логировать** эти вызовы (клиент, O, R, время; для
  привязки к заказу — добавить `order_num` в запрос).
- **F** — из истории (`order_lines` = текущий срез; `order_line_versions` = версии,
  уже пишутся на каждый ingest).

---

## 2. Три категории эффекта

| Категория | Формула | Метод | Данные |
|---|---|---|---|
| **A. Прямой** | `(F − O) ∩ R` | рекомендованное попало в заказ | журнал рекомендаций + состояния заказа |
| **B. Косвенный** | рост без рекомендованных (тип 1B) | сравнение когорт «с ассистентом» vs «исключённые» | история + журнал (кто получал рекомендации) |
| **C. Потенциал** | `R − (F − O)` | рекомендовали, не взяли | журнал рекомендаций + состояния заказа |

**Сценарии №1 и №2 — оба категория A:**
- **№1** — рекомендованное добавлено в **тот же** заказ: `R ∩ (F − O)` этого заказа.
- **№2** — рекомендованное всплыло в **новом** заказе клиента в пределах **срока
  жизни рекомендации** (TTL журнала): `R(клиент) ∩ состав заказа`. Связь — по
  журналу **на уровне клиента**, без сопоставления заказов.

Категория **B** — исходный тип 1B (рост не рекомендованными позициями). Меряется
не матчингом, а сравнением когорт; когорты выводятся из журнала (был вызов
`/analyze` → «с ассистентом»; не было → исключён). Дата включения = первый вызов.

---

## 3. Денежный эффект

`прирост тоннажа × удельная EBITDA (₽/тн)`. Считать ли конверсию по созданию заказа
или по отгрузке — открытый вопрос (§6).

---

## 4. Данные и реализация

**От 1С — ничего нового.** Полную историю уже получаем (даёт F и когорты).

**Наша сторона (расширить хранение):**
1. **Журнал рекомендаций** — персистить вызовы `/api/analyze` (клиент, O, R, время;
   `order_num` для привязки). Даёт O, R, знаменатель `N`, когорты для B.
2. **Версии заказа** — `order_line_versions` (готово), для F и O→F диффа.

**Внешний пробел (не 1С-контракт):** данные об **отгрузке** (если конверсия по
отгрузке) + **удельная EBITDA** — предположительно один источник.

**Статус кода:**
- ✅ `order_line_versions` — снимки версий заказа + `repository.get_order_diff`.
- ✅ Фид отгрузок (`shipment_lines`), рекомендации строятся из отгрузок.
- ⏳ Витрина эффекта (воронка: дифф заказа O→F + отгрузки) — Фаза 4.
- 🗑 Маркер-эпоха удалена: колонки `rec_*` и файлы `db/effect_metrics*.sql`
  вычищены (маркер от 1С в текущей модели не используется).

---

## 5. Витрина для PowerBI

Представление по строкам «сценарий × тип эффекта (A/B/C)» × отрасль × месяц:
число заказов, прирост тоннажа, денежный эффект. Строится по журналу рекомендаций +
состояниям заказа. Знаменатель `N` — из журнала (заказы с рекомендациями).

---

## 6. Открытые вопросы

1. **`order_num` в `/api/analyze`** — добавить для привязки рекомендаций к заказу.
2. **Срок жизни рекомендации (TTL журнала)** — значение (по умолчанию 2 раб. дня).
3. **Конверсия** — по созданию заказа или по отгрузке.
4. **Отгрузка + EBITDA** — источник и гранулярность.
5. **Исключения ассистента** (отрасли/клиенты) — где ведутся (для когорт B).
6. **Единица `qty`** — тонны.
