# Архитектурное решение — на согласование с ИБ

Сервис аналитики продаж (кросс-сейл рекомендации для менеджеров по металлопрокату).
Документ описывает архитектуру, потоки данных и меры защиты для согласования с
информационной безопасностью. Отдельно разделены **текущее состояние (тестовый
стенд)** и **требования к продуктивному развёртыванию**.

> Пометки: **[тек]** — как сейчас на тестовом стенде; **[прод]** — обязательное
> требование к продуктиву. Реестр рисков — в §9.

---

## 1. Назначение и область

Внутренний сервис, который по истории заказов клиента и текущей заявке возвращает
рекомендации (забытые/нишевые позиции). **Интеграция read-only со стороны сервиса:**
сервис только принимает данные и отдаёт рекомендации, **в 1С ничего не пишет** и
никуда данные не отправляет.

Область согласования — сам сервис (backend + БД + фронт-прокси) и его развёртывание.

---

## 2. Классификация данных

| Данные | Что | Чувствительность |
|---|---|---|
| История заказов | GUID клиента/подгруппы/товара, `order_num`, дата, кол-во (тонны), отрасль | **Коммерческая тайна** (данные продаж) |
| Наименование клиента | `client_name` — название **юрлица** (ООО …) | Коммерческая тайна |
| Рекомендации | подгруппы/товары (GUID) | Производная от истории |

**Персональные данные (152-ФЗ):** сервис **не хранит ПДн физлиц**. `client_name` —
это юрлицо; идентификаторы менеджеров/операторов не сохраняются.

**Минимизация данных (сильная сторона):** идентичность — **по GUID**; наименования
товаров и подгрупп **не хранятся** (их резолвит 1С). То есть в БД сервиса — по сути
**псевдонимизированные** ссылки + количества, без «читаемого» товарного состава.

---

## 3. Компоненты и развёртывание

Стек: **FastAPI (uvicorn, Python 3.12) + PostgreSQL 16**, в **Docker Compose**.

```
                         host (self-hosted)
   ┌───────────────────────────────────────────────────────┐
   │  nginx (reverse-proxy)  →  api (uvicorn :5050)          │
   │        :99 (TLS-term)         │                         │
   │                               ▼                         │
   │                         PostgreSQL 16                   │
   │                         (только внутри сети compose,    │
   │                          на хост НЕ публикуется)        │
   │                         worker (пересчёт агрегатов)     │
   └───────────────────────────────────────────────────────┘
```

- **api** — HTTP API (uvicorn), слушает `127.0.0.1:5050` (наружу только через nginx).
- **db** — PostgreSQL, доступен **только внутри сети Docker Compose** (порт на хост
  не пробрасывается).
- **worker** — фоновый пересчёт аналитических агрегатов (без внешних вызовов).
- **nginx** — единственная точка внешнего входа, TLS-терминация **[прод]**.

**[тек]** Внешний доступ: `http://sgsales.rumsk01.keenetic.link:99` — проброс
WAN:99 на хосте через роутер, nginx проксирует на api. **Трафик по HTTP, без TLS.**

---

## 4. Потоки данных

```
1С ──(1) POST /api/ingest/order-lines──► сервис ─► БД (сырьё) ─► агрегаты
                                                                   │
оператор/1С ──(2) POST /api/analyze {клиент+позиции}──► сервис ─► рекомендации (в ответе)
```

- **(1) Приём истории** — 1С пушит дельту заказов (право `ingest`). Сервис
  складывает и пересчитывает агрегаты.
- **(2) Анализ заявки** — приходит клиент + позиции заявки (право `analyze`), в
  ответе — рекомендации. **Заявка не сохраняется** (stateless).
- **Исходящих соединений у сервиса нет** — он самодостаточен, во внешние системы
  данные не отправляет. Единый канал — 1С (входящий).

---

## 5. Аутентификация и авторизация

Модель **machine-to-machine (M2M)**, пользовательской (human) аутентификации в
сервисе нет.

- Клиент (1С/интегратор) обменивает `client_id` + `client_secret` на
  `POST /api/auth/token` → получает **подписанный сервером JWT (HS256)** с областями
  (`ingest` / `analyze`), TTL ~1 час.
- Защищённые эндпоинты принимают **только валидный выданный токен** с нужным scope
  (`Authorization: Bearer <token>`). Нет/просрочен → `401`; без права → `403`.
- Секреты клиентов и ключ подписи задаются конфигурацией (§7).

| Субъект | Права (scope) | Действия |
|---|---|---|
| 1С (интегратор) | `ingest` (+ `analyze`) | загрузка истории, анализ |
| Оператор через 1С | `analyze` | анализ заявки |
| Администрирование хоста/БД | вне сервиса (ops) | развёртывание, доступ к БД |

**[прод]** Пустой ключ подписи (`AUTH_JWT_SECRET`) **отключает** авторизацию —
допустимо только локально. В продуктиве ключ **обязателен** (сервис громко
предупреждает при старте при пустом ключе).

---

## 6. Сетевая модель и поверхность атаки

- **Единственная точка входа** — nginx; api и db наружу напрямую не смотрят
  (api на `127.0.0.1`, db не публикуется на хост).
- Внешняя поверхность = 4 эндпоинта: `/api/auth/token`, `/api/ingest/*` (scope),
  `/api/analyze` (scope), `/health`. Плюс OpenAPI-схема `/docs` **[прод: закрыть/
  ограничить]**.
- `client_max_body_size 50m` (ingest-пачки).
- **[тек]** Внешняя экспозиция через проброс порта на роутере — доступ из интернета.
  **[прод]** Ограничить источники (allowlist IP 1С/оператора на nginx или firewall),
  либо перевести в частную сеть/VPN; убрать прямой WAN-проброс.

---

## 7. Шифрование и управление секретами

**Транспорт:**
- **[тек]** HTTP без TLS — токены и данные идут открытым текстом.
- **[прод]** **TLS обязателен** (терминация на nginx: `listen 99 ssl` + валидный
  сертификат), редирект HTTP→HTTPS.

**Данные at rest:**
- PostgreSQL на томе Docker. **[прод]** шифрование тома/дисков — по политике ИБ;
  резервные копии — шифровать.

**Секреты:**
- `AUTH_JWT_SECRET` (ключ подписи HS256, `openssl rand -hex 32`), `AUTH_CLIENTS`
  (секреты клиентов), учётные данные БД.
- **[тек/прод]** Задаются через **защищённые CI/CD-переменные** (masked + protected)
  → пишутся в `.env` на хосте при деплое; в репозитории секретов нет.
- **[прод]** Сменить дефолтные учётки БД (`agsales/agsales`) на сильные; ограничить
  права файла `.env`; предусмотреть **ротацию** ключа подписи и секретов клиентов.
- Секреты клиентов передаются 1С по защищённому каналу (не в репозитории/письмах).

---

## 8. Логирование, аудит, хранение

- **Логирование:** технические логи api/worker (uvicorn). **[прод]** гарантировать,
  что в логи **не попадают** токены, секреты и тела с данными.
- **Аудит доступа:** факт вызовов (эндпоинт, scope) — на уровне nginx/api-логов.
- **Хранение/ретенция:** история — накопительно (дельта, удалений нет); политику
  ретенции и **резервного копирования** согласовать с ИБ.
- **Планируемое расширение (метрики эффекта):** журнал рекомендаций — сервис начнёт
  сохранять свои ответы `/analyze` (клиент, состав, время). Это та же категория
  данных (коммерческая тайна, GUID), без новых типов ПДн.

## 9. Реестр рисков и меры

| # | Риск | Текущее состояние | Мера | Приоритет |
|---|---|---|---|---|
| 1 | Трафик без TLS (открытые токены/данные) | [тек] HTTP:99 | TLS-терминация на nginx, редирект | **Высокий** |
| 2 | Внешняя экспозиция через проброс роутера | [тек] WAN:99 → хост | Allowlist IP / firewall / VPN; убрать прямой проброс | **Высокий** |
| 3 | Пустой ключ = авторизация выключена | Предупреждение при старте | Обязательный ключ в проде (при желании — fail-fast) | **Высокий** |
| 4 | Дефолтные учётки БД | `agsales/agsales` | Сильный пароль в секретах; БД не публикуется (уже) | Средний |
| 5 | Симметричный ключ HS256 (подделка при компрометации) | Один секрет | Длинный секрет, ротация, секрет-хранилище | Средний |
| 6 | Секреты в `.env` на хосте | Из CI (masked+protected) | Права файла, запрет логирования, ротация | Средний |
| 7 | Открытый `/docs` (OpenAPI) | Доступен | Ограничить/закрыть в проде | Низкий |
| 8 | Устаревание зависимостей/образов | — | Регулярные обновления, сканирование образов | Средний |
| 9 | Резервные копии / ретенция | Не формализовано | Политика бэкапов (+ шифрование) по требованиям ИБ | Средний |

---

## 10. Чек-лист готовности к продуктиву (для ИБ)

- ☐ TLS включён (валидный сертификат), HTTP→HTTPS редирект.
- ☐ Внешний доступ ограничен по источникам (IP allowlist / VPN).
- ☐ `AUTH_JWT_SECRET` задан (длинный, случайный); авторизация активна.
- ☐ Учётки БД сменены с дефолтных; БД недоступна с хоста/извне.
- ☐ Секреты — только в защищённых CI-переменных; `.env` с ограниченными правами.
- ☐ `/docs` закрыт или ограничен.
- ☐ Логи без секретов/токенов; настроены бэкапы (шифрованные) и ретенция.
- ☐ Процедура ротации ключа подписи и секретов клиентов.
