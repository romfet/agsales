# Концепция расчёта эффекта ИИ-ассистента — на согласование

Документ фиксирует **подход** к расчёту эффекта до реализации. Просьба
подтвердить решения раздела 3 — после согласования переходим к реализации, не
переделывая концепцию. Детали — в документах «Метрики эффекта ИИ-ассистента» и
«Интеграция с 1С».

---

## 1. Концепция в двух словах

**Как меряем эффект.** Когда ассистент рекомендует позицию и менеджер её
принимает, позиция попадает в заказ с **пометкой «добавлено по рекомендации ИИ»**
(и указанием, в каком заказе она была рекомендована). Эффект = **прямой подсчёт
таких помеченных позиций**. Мы не пытаемся «угадывать» задним числом, что и когда
было рекомендовано, — фиксируем факт в момент принятия. Это делает расчёт
**точным и проверяемым**.

**Два сценария (по жизни заказа).** Заказ в 1С живёт ~2 дня, затем закрывается:
- **Сценарий №1** — рекомендованная позиция добавлена в **тот же** заказ (пока он открыт);
- **Сценарий №2** — рекомендованная позиция ушла в **новый** заказ (после закрытия исходного).

Сценарий определяется автоматически по пометке (в каком заказе рекомендовано vs в
какой попало).

**Конверсия.** За реализацию эффекта принимаем **факт создания** заказа с принятой
рекомендацией (см. решение 2).

---

## 2. Что нужно с вашей стороны, чтобы концепция работала

1. Ассистент/интерфейс менеджера **фиксирует принятие** рекомендации.
2. 1С проставляет на строке заказа **пометку рекомендации** (признак + тип +
   заказ-источник) и передаёт её в сервис вместе с историей.
3. Источник **числа заказов, где ассистент отработал** — для расчёта долей и
   конверсии (см. решение 3).

## 3. Решения на согласование

По каждому пункту — наше предложение. Просьба подтвердить или скорректировать.

| # | Вопрос | Наше предложение | Подтверждение |
|---|---|---|---|
| 1 | **Механизм измерения** | Пометка рекомендации на строке заказа (а не восстановление задним числом) | ☐ согласовано / ☐ иначе |
| 2 | **Конверсия — по чему** | По **факту создания** заказа. Отгрузку **не** учитываем: доедет заказ или нет — зависит от остатков/логистики/оплаты, на что ассистент не влияет | ☐ согласовано / ☐ нужна отгрузка |
| 3 | **Знаменатель долей/конверсии** | Брать число отработанных заказов из счётчика показов ассистента **или** списка незаисключённых заказов — нужно определить источник | ☐ счётчик показов / ☐ список из 1С |
| 4 | **Пометку проставляет** | 1С + интерфейс ассистента (при принятии рекомендации) | ☐ готовы / ☐ обсудить |
| 5 | **Исключения ассистента** | Ведутся по отраслям и клиентам; нужно договориться, где хранятся | ☐ в 1С / ☐ в сервисе |
| 6 | **Сценарий №1 «рост количества» по существующей позиции** | Учитывать, если 1С передаёт изменения заказа в течение его жизни; иначе считаем только добавленные **новые** позиции | ☐ передаём изменения / ☐ только новые позиции |
| 7 | **Эффект 1B (рост без рекомендованных позиций)** | Спорный (под него подпадает почти любой рост). Предлагаем на первом этапе **не** включать | ☐ не включаем / ☐ включаем, критерий: … |
| 8 | **Удельная EBITDA** | Внешний справочник; уточнить гранулярность (общая / по группе / по периоду) | ☐ источник: … |
| 9 | **Единица количества** | Тонны | ☐ да / ☐ иная |

## 4. После согласования

- Финализируем контракт передачи пометки и дашборд эффекта.
- Реализация базовых механизмов уже начата (сервис принимает и хранит пометку) —
  дорабатываем строго под согласованную концепцию.
