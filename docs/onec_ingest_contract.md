# Контракт приёма истории (1С → сервис, push) — внутренний

Документ для команды 1С по загрузке истории. **Точный формат всех вызовов — в
`onec_api.md`** (канонично); здесь — семантика и договорённости.

Интеграция **read-only со стороны сервиса**. Идентичность по **GUID**: клиент →
`client_id`, отрасль → `niche` (GUID!), подгруппа → `n3_id`, товар → `n4_id`, заказ
→ `order_id`, отгрузка → `shipment_id`. `order_num`/`shipment_num` — номера для
отображения. Наименования товара/подгруппы не передаются (1С резолвит по GUID).
Транспорт — TLS, тела — JSON UTF-8.

> Остатки в интеграции **не участвуют**.

---

## 0. Что реализовать на стороне 1С

1. **Заказы** дельтой: `POST /api/ingest/order-lines` (ключ `order_id`; **присылать
   при каждом изменении** — держим версии), затем `POST /api/ingest/commit`.
2. **Отгрузки** (факт): `POST /api/ingest/shipments` (ключ `shipment_id`, ссылка
   `order_id`; заказ↔отгрузка m2m). **Обязательно — рекомендации считаются по отгрузкам.**
3. **Токен** на `POST /api/auth/token`; далее `Authorization: Bearer <token>`.
4. **Анализ** `POST /api/analyze` при разборе заявки оператором.

**Форматы строк** — `onec_api.md §2` (заказы) и `§3` (отгрузки). Заказ обязателен:
`order_id`, `order_num`, `client_id`, `niche`, `n3_id`, `n4_id`, `qty`. Отгрузка
обязательна: `shipment_id`, `order_id`, `client_id`, `niche`, `n3_id`, `n4_id`, `qty`.

**Подтвердить:**
- [ ] **GUID-ключи** — `order_id`, `shipment_id`, `client_id`, `niche`, `n3_id`,
      `n4_id` = ссылки объектов 1С (готовые GUID, без склеек);
- [ ] **заказы — дельта с версиями**: при изменении заказ присылается **целиком**
      по `order_id`;
- [ ] **отгрузки** — по `shipment_id` со ссылкой `order_id`; связь m2m; `qty` =
      фактически отгружено;
- [ ] **возвраты/корректировки** — как приходят и учитывать ли;
- [ ] источник GUID **`niche`** (Отрасль) в 1С;
- [ ] единица **`qty`** — тоннаж;
- [ ] готовность получать токен (секрет — по защищённому каналу).

**Что НЕ нужно передавать:** остатки. `order_id` в `/api/analyze` передаётся для
последующего расчёта эффекта; без него TOP-5 работает, но атрибуция невозможна.

## 1. Авторизация

`POST /api/auth/token` → JWT со scope. Далее — `Authorization: Bearer <token>`.
`client_id`/`client_secret` выдаёт сервис. Право `ingest` — для `/api/ingest/*`,
`analyze` — для `/api/analyze`. Нет/просрочен токен → `401`; без права → `403`.
Формат — `onec_api.md §1`.

> auth-`client_id` приложения **не путать** с `client_id` контрагента в данных.

---

## 2. Заказы — `POST /api/ingest/order-lines`

Грейн — строка заказа `(заказ × товар)`, идентичность по GUID. Дельта: новые и
изменённые заказы. Заказ передаётся **целиком по `order_id`**: в загрузке должны быть
все его строки. Пачка 1 000–10 000 строк; строки одного заказа — в одной пачке
(сортировать по документу). В режиме `INGEST_MODE=staged` сервис собирает заказ и из
нескольких пачек одной загрузки (см. `onec_api.md`, «Пачки и документы»). Сервис хранит
**версии** заказа: `direct` — версия на пачку, `staged` — на сборку. Формат — `onec_api.md §2`.

## 3. Отгрузки — `POST /api/ingest/shipments`

Факт отгруженного. Ключ `shipment_id`, ссылка `order_id` (заказ↔отгрузка m2m).
Upsert по `shipment_id`: в загрузке должны быть все строки РТУ (правила пачек — как у
заказов), удалений нет, `qty` = фактически отгружено. **Обязателен:
рекомендации считаются по отгрузкам.** Формат — `onec_api.md §3`.

## 4. Финализация пачки — `POST /api/ingest/commit`

`direct`: пересобирает агрегаты (можно не звать: сервис пересобирает и по таймеру).
`staged`: отвечает 202 сразу; документы собираются по паузе в пачках. Вызывать один раз в
конце выгрузки, а не после каждой пачки. Формат — `onec_api.md §4`.

## 5. Анализ заявки — `POST /api/analyze` (scope `analyze`)

Клиент + текущие позиции заявки → рекомендации на уровне N4. `n4_id` должен
передаваться для каждой штатной строки. `order_id` необходим для последующего
расчёта эффекта в текущем или новом заказе. Формат — `onec_api.md §5`.

## 6. Ошибки и надёжность

- Коды: `200` ок; `400` некорректное тело / пустая заявка; `401` нет/просрочен
  токен; `403` без права; `5xx` — повтор с backoff.
- Ингест идемпотентен. Недоступность сервиса не должна ронять 1С.
