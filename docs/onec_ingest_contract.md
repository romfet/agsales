# Контракт обмена с 1С (push / HTTP)

Документ для команды 1С. **Содержание JSON задаёт сервис аналитики** (здесь).
Read-only со стороны сервиса: 1С передаёт данные, сервис ничего в 1С не пишет.

Два вызова:
- **История заказов** — раз в сутки, полный срез (`/api/ingest/order-lines` + `commit`).
- **Анализ заявки** — в реальном времени (`/api/analyze`): клиент + текущие позиции → рекомендации.

История = **ровно та же выгрузка, что Excel-файл «Результат…»**, плюс поле `client_id`.
Идентичность: клиент → `client_id` (+ `Клиент` для отображения); заказ → `ЗаказНомер`;
товар → `N4`; ниша → `Отрасль`; количество → `Количество` (единица не важна).

Общее: TLS обязателен; тела — **JSON, UTF-8**.

> Остатки в интеграции **не участвуют** — на рекомендации они не влияют; если нужно,
> 1С показывает их оператору сама рядом с возвращёнными товарами.

---

## 1. Авторизация (запрос токена → JWT)

```
POST /api/auth/token            Content-Type: application/json
{ "client_id": "onec", "client_secret": "<секрет>" }
→ { "access_token": "<JWT>", "token_type": "bearer", "expires_in": 3600, "scope": "ingest" }
```
Далее в каждом вызове: `Authorization: Bearer <access_token>`.
- `client_id`/`client_secret` выдаём мы (разово). Токен живёт `expires_in` сек.
- Право `ingest` — для `/api/ingest/*`; `analyze` — для `/api/analyze`.
- Нет/просрочен токен → `401`; токен без нужного права → `403`.

> auth-`client_id` приложения-интегратора **не путать** с `client_id` контрагента в данных.

---

## 2. История заказов — `POST /api/ingest/order-lines`

Грейн — **строка заказа (позиция)** `(заказ × товар)`, плоско. Поля — как в
Excel-выгрузке + `client_id`.

```
POST /api/ingest/order-lines     Authorization: Bearer <access_token>
Content-Type: application/json
```
```json
{
  "items": [
    {
      "client_id":   "c0ffee00-0000-0000-0000-000000000012",
      "Клиент":      "Клиент 12",
      "Отрасль":     "04. Металлотрейдеры",
      "ЗаказНомер":  "АГAG-212482",
      "ЗаказДата":   "2024-08-11",
      "N1":          "02. ТРУБЫ ПРОФИЛЬНЫЕ",
      "N2":          "02.01. Трубы профильные до 120",
      "N3":          "02.01.01. Трубы профильные до 120 Ст1-3, Ст10-20, C235-С285",
      "N4":          "Труба профильная 40х20х2 Углерод.",
      "Количество":  1.032
    }
  ]
}
```

### Поля

**Обязательные:** `client_id` (ключ клиента), `Отрасль` (ниша = мода по клиенту),
`ЗаказНомер` (ключ заказа → счёт уникальных заказов для частоты), `N3` (уровень
сопоставления), `N4` (товар), `Количество` (объём).

**Опциональные:** `Клиент` (имя), `ЗаказДата` (давность), `N1`, `N2`.
Колонку `Дата` слать не нужно — не используется.

### Семантика — суточный полный срез

Раз в сутки 1С шлёт **полную историю** пачками (1 000–10 000 строк), затем
`POST /api/ingest/commit` (§3) — атомарная замена среза + пересчёт агрегатов.
До `commit` работает прежний срез. Удаления не нужны — чего нет в новом срезе,
того нет. Ответ на пачку: `{ "accepted": <строк> }`.

---

## 3. Финализация суточной загрузки — `POST /api/ingest/commit`

```
POST /api/ingest/commit          Authorization: Bearer <access_token>
→ { "status": "ok", "rows": <в новом срезе> }
```
Вызывается после последней пачки истории.

## 4. Анализ заявки — `POST /api/analyze` (scope `analyze`)

**Stateless**: прислали клиента + текущие позиции заявки → в ответе рекомендации.
Анализ на уровне **N3**.

```
POST /api/analyze                Authorization: Bearer <access_token>
Content-Type: application/json
```
```json
{
  "client_id": "c0ffee00-0000-0000-0000-000000000012",
  "lines": [
    { "N4": "Труба профильная 40х20х2 Углерод.", "qty": 1.5 },
    { "N4": "Арматура ф 14 А500С", "qty": 2.0 }
  ]
}
```
- `client_id` — чей заказ. `lines` — позиции (`N4` + `qty`; можно `N3` вместо `N4`).
- Номер/id самого заказа не нужен (заявка не сохраняется).

Ответ — `{ client_id, niche, analysis1_forgotten[], analysis2_niche[] }`
(поля рекомендаций — см. `onec_integration.md §4.2`).

---

## 5. Ошибки, надёжность

- Коды: `200` ок; `400` некорректное тело / пустая заявка; `401` нет/просрочен токен;
  `403` токен без права; `5xx` — повтор с backoff.
- Ингест истории идемпотентен. Недоступность сервиса не должна ронять 1С.

---

## 6. Что обеспечивает сторона 1С

1. **История** — раз в сутки, **полный срез**, пачки + `commit`; `client_id` = `Ссылка`
   контрагента, остальные поля как в Excel-выгрузке.
2. **Состав истории** — проведённые заказы; возвраты/отмены не включать в срез.
