# Математика рекомендаций и прямого эффекта

Актуальная модель сервиса после перехода рекомендаций на товарный уровень N4.
N3 сохраняется как родительская группа и для обратной совместимости старой BI-витрины.

## 1. Источники

- `shipment_lines` — реализованная история для расчёта рекомендаций;
- `order_line_versions` — первая и последняя версии заказов;
- `recommendation_log` — показанные пользователю рекомендации;
- `client_profile_n4`, `niche_profile_n4` — материализованные N4-профили;
- `recommendation_effect_n4` — подтверждённый отгрузкой прямой эффект.

Существующие запросы загрузки из 1С не изменяются: строки заказов и РТУ уже содержат
`client_id`, `order_id`, `n3_id`, `n4_id` и `qty`.

## 2. Гранулярность

- N3 — подгруппа товара;
- N4 — конкретная товарная позиция (SKU);
- TOP-5 и прямой эффект рассчитываются по N4;
- `n3_id` возвращается вместе с N4 как родительская группа;
- один заказ с несколькими РТУ считается одним заказом при расчёте частоты.

## 3. Профиль клиента N4

Одна строка на `(client_id, n4_id)`:

```text
order_count        = число уникальных order_id клиента с N4
shipment_count     = число уникальных shipment_id клиента с N4
total_orders       = число уникальных реализованных заказов клиента
total_shipments    = число уникальных РТУ клиента
frequency_pct      = order_count / total_orders × 100%
avg_qty_per_order  = сумма qty N4 / order_count
total_qty_12m      = отгруженный объём N4 за последние 12 месяцев
```

## 4. Профиль ниши N4

Одна строка на `(niche, n4_id)`:

```text
client_count       = число уникальных клиентов ниши, покупавших N4
order_count        = число уникальных заказов ниши с N4
shipment_count     = число уникальных РТУ ниши с N4
niche_pct          = client_count / total_clients_in_niche × 100%
niche_freq_pct     = order_count / total_orders_in_niche × 100%
avg_qty_per_client = сумма qty N4 / client_count
total_qty_12m      = отгруженный объём N4 в нише за последние 12 месяцев
```

## 5. TOP-5 клиента

Кандидатом является N4, которая:

1. встречается не менее чем в 5% реализованных заказов клиента;
2. отсутствует в текущем заказе;
3. не относится к N3-only строке текущего заказа, для которой неизвестен конкретный N4.

Сортировка стабильная:

```text
frequency_pct DESC,
order_count DESC,
shipped_qty DESC,
n4_id ASC
```

После фильтрации возвращается до пяти позиций. Слабые позиции для формального
заполнения пяти строк не добавляются. Тип рекомендации — `missing`.

## 6. TOP-5 ниши

Кандидатом является N4, которая:

1. покупалась не менее чем 5% клиентов ниши;
2. отсутствует в текущем заказе;
3. не попала в TOP-5 клиента;
4. не относится к N3-only строке текущего заказа.

Сортировка:

```text
niche_freq_pct DESC,
order_count DESC,
shipped_qty DESC,
n4_id ASC
```

Возвращается до пяти позиций. Списки независимы; ниша не заполняет недостающие
строки клиентского списка. Одинаковая N4 может появиться только в одном списке,
приоритет имеет персональная рекомендация клиента.

## 7. Текущий заказ

Штатно каждая строка `/api/analyze` передаёт `n4_id`. Сервис сохраняет N4 при
нормализации и при необходимости резолвит родительский N3.

Для обратной совместимости принимается строка только с `n3_id`. Поскольку конкретный
товар неизвестен, все N4 этой N3 исключаются из рекомендаций. Запрос не отклоняется.

## 8. Прямой эффект рекомендованной N4

В прямой эффект входит только позиция, которая одновременно:

1. была показана в TOP-5 клиента или TOP-5 ниши;
2. отсутствовала в исходной версии заказа;
3. была добавлена в тот же либо подходящий новый заказ;
4. была фактически отгружена.

### Сценарий `same_order`

Рекомендованная N4 появилась в финальной версии исходного заказа:

```text
realized_qty = min(final_qty_N4, shipped_qty_N4)
```

### Сценарий `new_order`

Рекомендованная N4 появилась в другом заказе того же клиента не позднее двух
рабочих дней после рекомендации. Рабочими считаются понедельник–пятница; официальный
календарь праздников пока не применяется.

```text
target.client_id = recommendation.client_id
target.order_id != recommendation.order_id
target.order_date входит в окно двух рабочих дней
realized_qty = min(final_qty_N4, shipped_qty_N4)
```

Чтобы исключить двойной учёт:

- повторные показы одной N4 в одном исходном заказе сворачиваются;
- целевая N4 нового заказа связывается с самой поздней подходящей рекомендацией;
- одна рекомендация связывается только с первым подходящим новым заказом;
- одна N4, попавшая в оба списка, логируется только один раз.

Денежный эффект рассчитывается внешним потребителем как:

```text
realized_qty × EBITDA на тонну N4
```

Удельная EBITDA пока не входит в действующий входной контракт.

## 9. Совместимость BI

Старая витрина `/api/effect/funnel` на уровне `(order_id, n3_id)` сохранена без
изменений. Точный прямой эффект N4 доступен через:

```text
GET /api/effect/recommendation-attribution
```

Ответ содержит источник рекомендации, целевой заказ, сценарий, N3/N4, заказанное,
отгруженное и зачтённое количество. Все агрегаты пересчитываются на `/api/ingest/commit`
и фоновым воркером.
